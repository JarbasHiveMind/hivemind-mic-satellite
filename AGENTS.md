# AGENTS.md — `hivemind-mic-satellite`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

hivemind-mic-satellite is the smallest satellite in the HiveMind ecosystem: it
runs only a microphone plugin and a VAD plugin on-device, streams every
VAD-gated voice segment upstream over `hivemind-bus-client`, and plays back the
synthesized speech the hive returns. Wakeword, STT, intent processing, and TTS
all happen on the hub — no local models. Part of the
[HiveMind](https://github.com/JarbasHiveMind) ecosystem — a protocol for
connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). The hub is
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core), with
[hivemind-audio-binary-protocol](https://github.com/JarbasHiveMind/hivemind-audio-binary-protocol)
providing server-side audio handling. The satellite speaks the wire protocol
through [hivemind-bus-client](https://github.com/JarbasHiveMind/hivemind-bus-client).
Related repos with more local processing: [HiveMind-voice-relay](https://github.com/JarbasHiveMind/HiveMind-voice-relay)
(local wakeword) and [HiveMind-voice-sat](https://github.com/JarbasHiveMind/HiveMind-voice-sat)
(full local stack).

## Layout / build / test

- Package module: `hivemind_mic_sat/` (single-file `__init__.py` plus
  `res/snd/`). Tests live in `tests/` (check before adding — do not create a
  second test directory); `tests/e2e/` holds the hivescope-driven end-to-end
  suite (real `hivemind-core` + this satellite over a real
  `HiveMessageBusClient`).
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[e2e]" --prerelease=allow`
- Run the suite in the foreground: `python3 -m pytest tests -q`. The e2e tests
  use `hivescope.pytest_fixtures` and need the `e2e` extra installed; they spin
  up a real hub, so they are slower than a unit suite — do not skip them for
  being slow.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is a
  bug to FIX at the source, not to work around with a pin downgrade.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- This is a thin app on top of `hivemind-bus-client`: it owns the mic/VAD
  capture loop, local playback, and CLI wiring, not the wire protocol or the
  Noise handshake. Identity/key persistence and reconnect logic live in
  `hivemind-bus-client` (`NodeIdentity`, `HiveMessageBusClient`) — bugs there
  belong upstream, not here.
- Bad or refused credentials must fail fast, matching the client library's
  contract: `run()` raises `RuntimeError` immediately when no `NodeIdentity` is
  set (no key/password/host and no prior `hivemind-client set-identity`); do
  not add retry loops here that mask an auth failure as a hang.
  Reconnect-after-drop behavior belongs to the underlying bus client, not to
  ad-hoc retry code in this repo.
  connect() is called once via `hm_bus.connect()` — respect the client's own
  handshake-retry bounds, don't wrap it in an unbounded loop.
- The satellite never runs its own wakeword/STT/TTS/intent processing; those
  are the hive's job, gated by the same access-key auth as every other
  satellite. Do not add local model inference here — it defeats the point of
  this being the cheapest-hardware satellite.
- Recording stop, when it happens, is a VAD/wakeword-boundary event, not an
  intent — do not route it through intent-handling code.
- Never hardcode secrets (access keys, passwords, hosts). Credentials come
  from `hivemind-client set-identity`, the persisted `NodeIdentity`, or CLI
  flags/env at invocation time.
- Document the real quickstart: `hivemind-core add-client` on the hub,
  `hivemind-client set-identity` on the device, then `hivemind-mic-sat` (or
  pass `--key/--password/--host/--port` directly). Keep README changes in sync
  with whatever the CLI actually accepts in `hivemind_mic_sat/__init__.py`.
